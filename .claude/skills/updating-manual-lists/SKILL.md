# Updating Manual Lists

## Overview

Several files in this repo are hand-curated from external documentation rather than generated by a script: every `allowlists/*.txt` file with a `# Sources:` block in its header, plus ad-hoc research-driven blocklists like `blocklists/whatsapp-tracking.txt`. Updating them means re-fetching each documented source and diffing it against the current file's entries — not running a scraper.

## Which files this covers

Any file with a `# Source:` / `# Sources:` block in its header:
`allowlists/ai-services.txt, apple.txt, avast.txt, aws.txt, easyllama.txt, general.txt, google.txt, microsoft-productivity.txt, online-shopping.txt, south-african-banking.txt, video-streaming.txt, whatsapp.txt`, and `blocklists/whatsapp-tracking.txt`.

Skip `allowlists/ublock_allowlist.txt` (hand-picked personal exceptions, not source-driven) and `regex_allowlist.txt` (regex, separate workflow) unless explicitly asked. Skip anything script-generated (`blocklists/malicious.txt`, `malicious_package_database/`, `blocklists/ublock/*`, `blocklists/privacy-badger/*`) — see the script prohibition below.

## Process (per file)

1. Read the file. Note its header source URLs and its stated scope/policy (e.g. "Functionality Only — Excludes: ads, tracking, analytics, telemetry").
2. For each source URL, WebFetch it asking for every domain/hostname mentioned. For research-style sources (Reddit threads, GitHub issues, blog posts), ask what's relevant to the file's specific topic instead.
3. Diff the fetched domains against what's already in the file.
4. For each candidate addition:
   - Skip templated/dynamic entries (`{{Region}}.foo.com`, per-tenant IDs, per-instance IDs) — only add concrete hostnames.
   - Skip anything that violates the file's stated exclusion policy — see Telemetry policy below.
   - Verify it resolves with `dig +short <domain>`, checked **individually**, not in a bulk/parallel sweep — under load this resolver has produced false NXDOMAIN results for domains that are definitely live (it flagged `api.claude.ai` and `ebay.com` as dead in one run). Re-check anything suspicious on its own before acting on it.
   - Place it in the most specific matching file, not `general.txt` — e.g. Xbox domains belong in `microsoft-productivity.txt` (Microsoft-owned), not `general.txt`.
   - Add it under the right thematic section, matching the file's existing comment-banner style, with a source citation if the section doesn't already make that obvious.
5. Never delete an existing entry on a suspicion of it being dead without the same individual verification as step 4.
6. If a documented source itself is dead (404, expired domain), note it in the header comment with the date and status rather than silently dropping it — match the existing style, e.g. `(DEAD as of 2026-06-18, 404 — no official replacement found)`. If WebFetch simply can't reach a source (e.g. it refuses `reddit.com` outright) that's a tool limitation, not a dead source — don't mark it dead; try a corroborating source instead and say in your summary that the fetch was blocked.
7. Report a per-file summary at the end: what was added, and explicitly state "already current, no changes" for files with nothing new — don't skip a file silently.

## Telemetry / analytics policy

Files marked "Functionality Only" exclude ads, tracking, analytics, and telemetry by design. If a documented source mentions a telemetry/analytics/crash-reporting/feature-flag endpoint (statsig, sentry, datadog, amplitude, crashlytics, etc.):

- Don't add it as an active entry.
- If worth documenting, add it commented-out with a one-line reason, matching the existing convention (see the Sentry/analytics block in `ai-services.txt`).
- If it's a *tracker* worth blocking rather than allowing, it belongs in a blocklist (e.g. `blocklists/whatsapp-tracking.txt`), not an allowlist.

## Do NOT run the repo's scripts for this

`scripts/update_all_lists.sh` and the individual `ruby scripts/extract_*.rb` / `scrape_*.rb` scripts exist for a different purpose: malicious-domain/package scraping and regenerating the uBlock/Privacy Badger derived lists. They have no concept of per-file scope policy, section placement, or the `Sources:` comments this skill works from.

| Excuse | Reality |
|---|---|
| "The script would cover this faster" | It scrapes unrelated sources (security blogs, uBlock filter lists) — not the URLs in this file's header |
| "update_all_lists.sh updates everything" | It only touches `blocklists/malicious*`, `malicious_package_database/`, `blocklists/ublock/*`, `blocklists/privacy-badger/*` |
| "Same end result either way" | The script can't apply "Functionality Only" exclusions or decide which file a domain belongs in |

If asked to run those scripts specifically, that's a separate, legitimate task — just don't reach for them when the ask is "update the allowlists."

## Commit policy

Leave changes uncommitted for review unless explicitly asked to commit, same as any other work in this repo.
