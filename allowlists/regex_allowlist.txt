# Pi-hole Regex Allowlist
#
# Format: POSIX ERE, one regex per line.  Pi-hole stores these in the
# 'domainlist' table (type=2 = regex allow) via:
#   pihole --white-regex '(^|\.)example\.com$'
# or by adding this file URL as a Pi-hole v6 allowlist (type=1 adlist).
#
# The pattern  (^|\.)domain\.com$  matches:
#   domain.com          (exact root)
#   sub.domain.com      (any subdomain)
#   deep.sub.domain.com (arbitrarily deep)
#
# Use this file ONLY for domains where you need wildcard subdomain coverage
# that cannot be expressed as a finite plain-domain list.
# All other domains belong in the plain-domain allowlist files.
#
# Sources / references documented inline per entry.

# ── Steam ──────────────────────────────────────────────────────────────────────
# Valve's game-server CDN uses numbered subdomains (cs1–csN.steampipe.steamserver.net etc.)
# Adding the root covers all current and future subdomains automatically.
# Plain entry `steamserver.net` already in general.txt covers the root itself.
(^|\.)steamserver\.net$

# ── YouTube / Google Video ─────────────────────────────────────────────────────
# YouTube Shorts and regular video both stream from dynamically-numbered subdomains:
#   rr1.googlevideo.com, rr2---sn-4g5lzney.googlevideo.com,
#   manifest.googlevideo.com, redirector.googlevideo.com, etc.
# Adding googlevideo.com as a plain domain only allows the exact root.
# This regex covers ALL subdomains, which is required for playback to work.
(^|\.)googlevideo\.com$

# ── Malwarebytes / ThreatDown ──────────────────────────────────────────────────
# Malwarebytes uses a wide range of subdomains under mwbsys.com and mb-cosmos.com
# for telemetry, keystone licensing, CDN and cloud connectivity.
# Sources:
#   https://app-support.malwarebytes.com/docs/DOC-1652
#   https://support.threatdown.com/hc/en-us/articles/4413798711699
(^|\.)mwbsys\.com$
(^|\.)mb-cosmos\.com$
(^|\.)mbamupdates\.com$

# ── Atlassian ──────────────────────────────────────────────────────────────────
# Atlassian uses a large number of subdomains under atl-paas.net for internal
# services, CI/CD pipelines, and CDN assets.
# Source: https://support.atlassian.com/organization-administration/docs/ip-addresses-and-domains-for-atlassian-cloud-products/
(^|\.)atl-paas\.net$

# ── Tuya / Lifeaiot ───────────────────────────────────────────────────────────
# Tuya smart home devices use dynamic regional subdomains under lifeaiot.com.
# The m3-eu.lifeaiot.com entry in general.txt only covers one region.
(^|\.)lifeaiot\.com$

# ── Google CDN nodes (gvt1.com) ───────────────────────────────────────────────
# gvt1.com serves Chrome, Android app content via dynamically-numbered edge nodes
# (e.g. r1---sn-54gpivnu15-woce.gvt1.com). redirector.gvt1.com is explicitly in
# google.txt; this regex covers all dynamic subdomain variants.
(^|\.)gvt1\.com$

# ── Apple Push Notification Service ──────────────────────────────────────────
# APNs uses numbered courier subdomains (1-courier.push.apple.com, etc.).
# push.apple.com and gateway.*.push.apple.com are in apple.txt; this covers all variants.
(^|\.)push\.apple\.com$

# ── SharePoint Online ──────────────────────────────────────────────────────────
# SharePoint uses tenant-specific subdomains (tenant.sharepoint.com).
# sharepoint.com is in microsoft-productivity.txt; this covers all tenant subdomains.
(^|\.)sharepoint\.com$

# ── Microsoft svc.ms (SharePoint/OneDrive internal APIs) ──────────────────────
# Required for SharePoint and OneDrive internal API calls (ID 39).
(^|\.)svc\.ms$

# ── Internet Archive ──────────────────────────────────────────────────────────
# Item content is served from dynamically-numbered CDN servers:
#   ia800801.us.archive.org, ia600908.us.archive.org, ia903xxx.us.archive.org, etc.
# Core domains are also listed explicitly in general.txt.
# Source: https://archive.org
(^|\.)archive\.org$

# ── Tailscale ─────────────────────────────────────────────────────────────────
# Tailscale DERP relay servers use numbered subdomains (derp1-all through
# derp28-all.tailscale.com, count grows over time). This regex covers all
# DERP servers plus login/controlplane/log/pkgs and any future subdomains.
# Core domains are also listed explicitly in general.txt.
# Source: https://tailscale.com/kb/1082/firewall-ports
(^|\.)tailscale\.com$

# ── Avast / AVG ───────────────────────────────────────────────────────────────
# Avast uses many dynamic subdomains under avast.com (ff.avast.com subtree,
# update servers, cloud scanning) and avcdn.net (CDN for definitions and assets).
# Plain entries in avast.txt cover known specific hostnames; these regexes catch
# any additional subdomains Avast introduces without requiring a file update.
# Source: https://businesshelp.avast.com/Content/Products/SysReqs/FirewallReqs_Full.htm
(^|\.)avast\.com$
(^|\.)avcdn\.net$
(^|\.)avg\.com$

# ── MediaFire ─────────────────────────────────────────────────────────────────
# Download servers use dynamically-numbered subdomains (download1825.mediafire.com,
# download2389.mediafire.com, etc.). Plain entries in general.txt cover the root
# and www; this regex covers all download subdomains.
# Note: ww.mediafire.com (typosquat) is intentionally kept in malicious.txt.
(^|\.)mediafire\.com$
